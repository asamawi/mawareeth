### Cross-story boundaries (diff-scope review: adversarial, edge-case, verification-gap lenses)

- **F1 — Disagreeing-School previews fail in the Interview (8.7 ↔ 8.9). Fix now, blocks release.** `api/views.py:309` adds `revision` to every session preview body (8.9, `6dbda1b`). `parseChoice` in `web/src/api/case.ts:1349` accepts only the exact keys `status, basis, schools, rules[, presented]`, so a `choose_school` body (still produced by `api/preview.py:267` whenever the Schools disagree, e.g. grandfather + full brother) parses as `null`, and `fetchPreview` (`case.ts:1402`) returns `failed`. The user sees a preview failure instead of the School selector, and retrying cannot recover. Tests miss it: `web/src/api/case.test.ts` and `web/src/interview/preview.test.ts` cover `revision` only on available answers and `choose_school` only without `revision`. *Prevention:* when a server response gains a field, grep the strict web parsers (`hasExactKeys`) for that response, and keep one cross-language fixture per preview status that carries every envelope field.
- **F2 — Rollback-compatibility gate checks a modelled release order, not the real one (8.8 ↔ 8.10 ↔ 8.11). Fix before enabling schema 2.** `mawareeth/release_gates.py:39-41` checks only adjacent rows of `api/fixtures/snapshots/matrix.json`, which inserts an "8.8 dual reader" image between `02d3627` (reads only 1) and the 8.10 writer. Production will go straight from `02d3627` to the Epic 8 image. If `SNAPSHOT_WRITE_VERSION=2` or the backfill is enabled before a dual-reader image has been the rollback target, a rollback to `02d3627` cannot read converted cases. The writer defaults to 1 (`mawareeth/settings.py:346-352`), and `deferred-work.md:437` tracks backup and eligible-reader sequencing, but the gate gives false assurance. *Prevention:* derive the gate from the real prior slot's image or a recorded deployed-image inventory, not a hand-kept list.
- **F3 — Capacity gate counts any HTTP 200 preview as a successful sample (8.7/8.9 ↔ 8.11). Fix now (small).** `api/capacity.py:118-120` breaks on status 200 without checking the body's status, `presented` or `revision`, and no workload uses a disagreeing family, so F1 passed the gate. `api/test_capacity.py` never injects an unusable 200.
